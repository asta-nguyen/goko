# Multiple Claude and Codex accounts tasks

## Design

[Multiple Claude and Codex accounts](design.md)

## Global Constraints

- No change to `crates/protocol`, `crates/daemon`, the `goko.db` schema, or `session_create`'s arguments. Usage stays passive: no network call, token, auth file, or Keychain read.
- The Default account (id `default`) is implicit and never stored. Its launch argv is exactly today's. Its folder is `$CLAUDE_CONFIG_DIR` else `$HOME/.claude` (Claude), `$CODEX_HOME` else `$HOME/.codex` (Codex).
- Setting `accounts`: JSON `{"claude":{"active":"<id>","items":[{"id","name","dir"}]},"codex":{…}}`. Missing, malformed, or an unknown or removed active id reads as Default only / Default active.
- Non-default launch argv, Claude: `[/usr/bin/env, CLAUDE_CONFIG_DIR=<dir>, <claude>, --session-id, <id>, --settings, <json>]`; Codex: `[/usr/bin/env, CODEX_HOME=<dir>, <codex>]`. A folder with spaces stays one argv element; no shell string is built.
- Claude capture file for a non-default account: `usage/claude/<account-id>/<session-id>.json`; Default keeps `usage/claude/<session-id>.json`. The activity file path is unchanged.
- A non-default account whose folder no longer exists fails the launch with `invalid_argument` and a hint; the agent never recreates it.
- A session's account is derived from its argv (the `CLAUDE_CONFIG_DIR=` or `CODEX_HOME=` word after `env`, matched to an account's dir; none means Default; an unmatched word is labelled by the folder's last path component). Nothing is stored per session.
- Validation: name 1 to 40 characters after trim, unique per agent case-insensitively; folder absolute after `~` expansion, no NUL or newline, not the Default folder, unique per agent. An invalid add or rename stores nothing.
- Adding creates the folder with mode 0700 if missing, makes the new account the agent's active account, and links shared entries that exist in the Default folder and not in the new one, never overwriting. Claude: `projects`, `settings.json`, `CLAUDE.md`, `skills`, `commands`, `agents`, `plugins`, `hooks`. Codex: `config.toml`, `AGENTS.md`, `skills`, `prompts`. Never linked: `auth.json`, `.credentials.json`, `.claude.json`, Codex `sessions`. A link that fails is skipped and the add succeeds.
- Remove deletes the entry only, never the folder; removing the active account makes Default active. Default cannot be renamed or removed. Switching never changes a running session.
- `UsageSnapshot.claude` and `.codex` describe the active account; `accounts` is a map keyed `"<agent>:<account-id>"` of `{limits: Limit[] (non-empty, window order), updated_at}`; `claude.sessions` is merged across all Claude capture folders. Setting the active account refreshes the snapshot at once.
- UI appears only with two or more accounts for an agent: the chip reads `<Agent> · <active name>` and opens a menu (one row per account with the active one marked, name, limits and age or "no usage yet", then **Manage accounts…**); the chip stays visible without limits; the "+" menu item and the session rows show the account name in muted text. With one account the UI is exactly today's.
- `activity.rs` must treat `[env, NAME=value…, <bin>]` whose bin stem is `codex` as a Codex session.
- Sign in runs the agent's own login command, never a Goko login: Claude `env CLAUDE_CONFIG_DIR=<dir> <claude> auth login`, Codex `env CODEX_HOME=<dir> <codex> login`, with the account folder as `cwd` and title `Sign in · <name>`. It starts automatically after a successful Add and from a **Sign in** button on added rows only (never Default). It uses the existing `session_create` custom-command arguments (`command` plus `cwd`) and opens in the Unassigned workspace; a rejected sign-in leaves the account added and shows its message inline. Goko still never reads credentials and never shows login state.
