# Editor sync and conflicts tasks

## Design

[Editor sync and conflicts](design.md)

## Global Constraints

- A bare `=======` line is never a conflict marker; `<<<<<<<`, `|||||||` and `>>>>>>>` lines are. `conflict::has_markers` is the only marker predicate.
- Conflict `status` values: `both-modified`, `both-added`, `deleted-by-us`, `deleted-by-them`, `both-deleted`, `added-by-us`, `added-by-them`; "us" is the `HEAD` side, the inline editor's Current.
- Resolve actions are `current`, `incoming`, `keep`, `delete`; valid per kind: both-modified and both-added → `current`/`incoming`; deleted-by-us, deleted-by-them, added-by-us, added-by-them → `keep`/`delete`; both-deleted → `delete`. Button labels: Use Current, Use Incoming, Keep our version (deleted-by-them, added-by-us), Keep their version (deleted-by-us, added-by-them), Delete file. The backend re-reads status and rejects anything else.
- A whole-file resolve action is refused with the notice "save or discard the changes in {path} first" while `EditorState::path_is_dirty(path)`.
- Resolve, Abort and Continue run on the serialized git-write lane, take literal checkout-relative pathspecs, never force, and never commit (a merge Continue is the ordinary Commit).
- `Req::StageResolved` refuses markers unless `allow_markers` is true; the UI sets it only after the user confirmed the dialog.
- Abort asks for confirmation. Rebase, cherry-pick and revert Continue run `<op> --continue` with `GIT_EDITOR=true`, `GIT_TERMINAL_PROMPT=0` and a 120 s limit. While an operation is in progress the primary commit button reads "Continue" and is enabled when no conflict remains.
- The merge message is prefilled once per merge, only into an empty draft, from `MERGE_MSG` without comment lines.
- Background reads are quiet (no spinner, no success notice), one outstanding per kind, every 3 s (5 × the last read time when that is longer, at most 30 s), only while `view == Editor`, the window is focused, and no write is in flight.
- A dirty document is never overwritten by a disk check; Overwrite is an explicit button press.
- No new dependency and no file-system watcher.

### Task 7 — Background refresh of Changes
