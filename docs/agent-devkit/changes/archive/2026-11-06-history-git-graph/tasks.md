# Editor History: Git Graph style table tasks

## Design

[Editor History: Git Graph style table](design.md)

## Global Constraints

- `git_view.rs` stays read-only for Git state. No new Rust crate and no new npm dependency (`radix-ui` already ships `ContextMenu`). No change to `crates/protocol`, `crates/daemon`, `ResizableSplit`, or the functions and tests owned by the open change `2026-11-06-editor-commit-acp` (staging, commit box, ACP, `git_write.rs`, `acp.rs`).
- The `branch` argument is a full ref under `refs/heads/` or `refs/remotes/` that exists as a commit; anything else (including a leading `-`) is `invalid` and no `git log` runs. `None` keeps the scope `--branches --tags --remotes`.
- Layout is persisted under `localStorage` key `goko.history.layout` as JSON `{graph?, date, author, commit, detailHeight}`; an invalid, missing, or throwing value means defaults.
- Sizes: row 28 px; Date 120, Author 128, Commit 80 px by default; user-set column 56–360 px; Graph natural width (14 px per lane plus padding) clamped 48–320 px; Description floor 200 px; detail default 320 px, minimum 160 px; table minimum 120 px; handle steps 16 px (64 px with Shift), `Home`/`End` for min/max, double-click restores the default.
- The graph palette has 8 colours; a branch line keeps its colour from start to end; a new lane takes the next unused colour in rotation; edges are vertical runs with a rounded bend, never straight diagonals. HEAD is a hollow ring; a commit with two or more parents has a centre mark.
- Rows are never hidden by the filter: non-matching rows are dimmed, the count reads `N matches`, `Enter`/`Shift+Enter` select the next/previous match. Selection happens only on click, `Enter`, or `Space`; `↑`/`↓`/`Home`/`End` move focus only.
- Dates show relative time through `Intl.RelativeTimeFormat` ("just now" under a minute) and the medium date after 30 days; the `title` is the existing `formatTime`.
- The history query key stays prefixed `['git-history', projectId, checkoutPath, …]` so existing prefix invalidation matches. `GitViewDiff.detail` and `StatusEntry.added`/`removed` are `null`/absent outside commit diffs, and `added`/`removed` are `null` for binary files.
- Row buttons keep `data-nav-item`, `aria-pressed`, and an accessible name that contains the subject, so the global `j`/`k` and the existing HEAD-row test keep working.

Update the existing `history(&root, N)` test calls to pass `None`.
